# ADR: Pack 封面策略——官方封面优先，生成式兜底

- 状态：已接受（2026-08-17 修订：引入 pack 自带封面优先）
- 日期：2026-08-17

## 背景与约束

Shopify 式商城的商品卡依赖产品图。pack 是纯 markdown 知识包，数据格式
（`index.json` + `page.mdx`）原本不含封面字段；新增 pack 的方式是往 `packs/`
丢一个目录。初版采用纯生成式封面，但用户反馈：对真实产品（如 hermes），
官方封面图远好于自绘 monogram。

## 决策

两级封面策略：

1. **Pack 自带封面优先**：pack 目录下放 `cover.png|jpg|jpeg|webp|svg|gif`
   （优先取官网/官方 OG 图）， storefront 通过 `/packs/<slug>/cover.*` 引用；
   `index.json` 的 files 列表应包含该文件，保证下载流程一并拉取。
2. **生成式封面兜底**：无 `cover.*` 的 pack 仍由 slug 哈希确定性生成
   渐变 + SVG 纹理 + 首字母 monogram 封面，新 pack 丢目录即有封面。

配套改动：`/packs/[...path]` 路由按扩展名返回正确的图片 MIME（此前一律
text/plain）。商品卡封面统一 16/10，详情页横幅统一 16/9，两种封面类型同版式。

## 备选方案

- **纯生成式封面（初版）**：零素材负担但被用户否决——真实产品配自绘
  monogram 观感差。
- **只认官方封面、无兜底**：新 pack 上架即破版，违背「丢目录即上架」。否决。
- **外链引用官方图**：运行时外部依赖 + 链接腐烂风险。否决，图片落进 pack。

## 权衡与后果

- 上架流程多一个可选步骤：放 `cover.*` 并登记进 `index.json`；不放也能用。
- 官方图版权归产品方；本店为产品介绍语境下的引用，风险可接受。
- 「同 slug 必同图」契约对两级都成立：自带封面是静态文件，生成式是确定哈希。

## 验证

- hermes 使用官方 OG 图（1200×692）渲染商品卡与详情页横幅截图核对；
- 无封面 pack（临时构造）回退到生成式封面截图核对；
- `npm run build` 通过。
