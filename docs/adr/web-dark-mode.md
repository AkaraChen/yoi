# ADR: 商城暗色通过 `prefers-color-scheme` 重映射语义令牌

- 状态：已接受
- 日期：2026-08-21
- 取代：`docs/adr/web-visual-system.md` 中「深色主题：否决」一条

## 背景与约束

令牌已集中在 `web/app/globals.css`，组件走语义色（`bg-background`、
`text-foreground` 等）。产品要求跟随系统且不放开关，因此不能引入
可写的主题状态。Tailwind 虽配置了 `darkMode: ["class"]`，仓库里没有
`dark:` 工具类，也没有主题脚本。

暗色必须是 Cursor 暖调的对应面：暖棕黑底，而不是中性灰黑。Cursor 暗色
底色 `#14120b` 与现有 `--terminal` 同值；若页面背景也用这个值，安装
命令条会沉进页面、失去井的层次。

## 决策

1. **切换机制**：在 `:root` 用 `@media (prefers-color-scheme: dark)`
   重写同一批 HSL 变量。无 JS、无 `next-themes`、不给 `<html>` 加
   `class="dark"`。未匹配暗色媒体查询时，浅色变量保持原值。
2. **暗色色板**（由 Cursor DNA 推导，不是新风格）：
   - 页面背景用卡片阶第一档 `#1b1913`，比终端井 `#14120b` 高一阶，
     命令条和终端卡片在暗色页上仍能读出来。
   - 前景 / `primary` 随主题反相：暗色下「墨」是 `#edecec`，主按钮
     因此变成浅色填充（Cursor 的 ink-pill 规则）。公告条与收尾 CTA
     不是按钮，使用不反相的 `--ink` / `--ink-foreground`：浅色下与
     原 `primary` 同值，暗色下为比页底高一阶的暖墨 `#26241e`，浅色字。
   - `--accent` 仍是焦橙 `#f54e00`；`--terminal*` 保持现有暖黑与
     ANSI / salmon，两种外观下终端都不反相。
3. **原生控件**：`html` 声明 `color-scheme: light dark`，滚动条等
   系统控件跟随外观。`theme-color` 元数据按媒体查询分别给出浅色纸白
   与暗色页底。
4. **组件**：公告条与收尾 CTA 改走 `bg-ink`；不添加 `dark:` 条件类。
   封面生成色板保持独立插画，不随主题改。

## 备选方案

- **`next-themes` + 导航开关**：产品已排除手动切换；额外客户端状态
  和闪屏防护都没有收益。否决。
- **inline script 按 `matchMedia` 写 `class="dark"`**：观感与纯 CSS
  相同，却引入首屏脚本和 hydration 注意事项。在「只跟系统」前提下
  没有必要。否决。
- **逐组件写 `dark:` 工具类**：会把主题决策打散，违背「只动令牌」
  的视觉系统契约。否决。
- **页面背景也用 `#14120b`**：与终端令牌撞车，安装条失去层次。否决。

## 权衡与后果

- 以后若要加手动切换，需要另做主题状态，本 ADR 的纯媒体查询不够用。
- 公告条与收尾 CTA 使用 `--ink`，暗色下保持暖墨带，不随 `primary`
  反相成浅色块。ink-pill 反相只作用于真正的主按钮。
- 业务组件若再硬编码浅色（如 `bg-white`），暗色会漏光；继续禁止。

## 验证

- 系统暗色：首页 / `/shop` / 详情页为暖黑底、浅色字、焦橙点缀；
  终端与命令条仍是更深的暖黑井；公告条与收尾 CTA 为暖墨带，不是浅色块。
- 系统浅色：与本 ADR 之前的截图观感一致。
- 页面源码与导航中不存在主题开关。
