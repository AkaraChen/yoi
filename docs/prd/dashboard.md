# PRD: Dashboard（服务器探针面板）

## 问题与背景

yoi 是个人部署栈的自托管 OS，操作者是用户的编码 Agent。人偶尔需要看一眼
现场：这台机器现在怎么样，上面记录的每个服务现在怎么样。Dashboard 是跑
**在自己服务器上**的只读探针 / 审计面——单二进制、低占用、只监听本机——
不是给人点按钮的控制面板（见 `docs/adr/agent-as-operator.md`）。

## 目标用户

- 服务器的拥有者本人（单用户场景），通过 SSH 隧道等方式从本机访问。

## 用户故事

- 作为服务器拥有者，我打开面板输入密码后，第一眼看到这台机器的关键
  指标（CPU/内存/磁盘/网络）。
- 作为服务器拥有者，我在侧边栏看到部署在这台机器上的服务列表，点进
  任意服务能看到它的运行状态、资源占用、部署记录和配套链接。
- 作为服务器拥有者，我点某个服务的外部链接（如配套的 Grafana）直接
  跳过去。

## 目标

- 仅监听 `127.0.0.1`，访问需要密码（信任边界：本机 + 密码）。
- 信息架构：左侧边栏 + 主内容区。侧边栏顶部是「服务器状态」条目
  （常驻压缩版关键指标），下方是服务列表；主内容区永远显示当前选中项
  的详情。服务器与服务平级，默认落地页是服务器概览。
- 服务器概览的指标采集面对齐哪吒探针：主机信息（hostname、OS/发行版、
  内核、架构、CPU 型号/核数、虚拟化类型、启动时间）与实时状态
  （CPU 使用率、内存/Swap、磁盘用量、网络上下行速率与累计流量、
  TCP/UDP 连接数、进程数、load1/5/15、运行时长）。
- 服务器概览用分段控件（segment control）切换「当前」（指标卡片）与
  「趋势」（近 1 小时时间窗口曲线：CPU、内存、网络上下行、负载；
  5 秒采样，内存环形缓冲，重启清零），两者不同屏展示。
- 服务详情页包含五块：合成状态；live 占用（或「无法探测」）；版本历史
  （Release 列表，可展开 plan/config/outcome）；事件时间线；外部链接。
- 服务数据来自本机 `~/.yoi/` store（yoi-server CLI 写入），探针只读。
  有 `runtime` 时资源区展示 live 占用；没有则「无法探测」。状态点为
  合成结果（见 `docs/prd/service-runtime-live.md`）。
- 视觉体系与 `web/` storefront 完全一致，token 来自 `design/`
  （见 `docs/adr/design-token-package.md`），文案中文。

## 非目标

- **跨重启的历史持久化**：趋势图只做内存环形缓冲（5 秒采样、保留最近
  1 小时），探针重启后历史清零（见 `docs/adr/dashboard-metrics-history.md`）。
- **服务实时实况的控制面**：本版只读探测，不提供启停。live 与合成状态
  见 `docs/prd/service-runtime-live.md`。
- 多机管理、告警、通知。
- 对服务的启停等控制操作（只读是定位，不是本版暂缓；见
  `docs/adr/agent-as-operator.md`）。
- 公网暴露、多用户、权限体系。

## 页面结构与用户流

### 登录门

- 未认证时只显示密码输入框；认证通过后进入面板。密码错误给出提示。

### 面板外壳

- 左侧边栏：顶部「服务器状态」条目（显示压缩版关键指标，如 CPU/内存
  占用），下方服务列表（每个服务显示名称与运行状态指示）。
- 主内容区：
  - 选中「服务器状态」（默认）→ 服务器概览页：主机信息 + 全部实时
    指标卡片。
  - 选中某服务 → 服务详情页：合成状态、live 或无法探测、版本历史
    （Release，可展开 plan/config/outcome）、事件时间线、外部链接。

## 用户可见状态与失败行为

- 服务状态点为合成结果（运行中 / 异常 / 已停止 / 无法探测），侧边栏与
  详情页一致。`removed` 的服务不进列表。
- 服务无外部链接时不渲染链接区；无事件时事件时间线显示空状态；无
  Release 时版本历史显示「从未部署」；侧边栏无服务时显示空列表态。
- 指标数据暂时不可得时显示占位（skeleton），不显示假数据。

## 验收标准

- 面板仅监听 localhost，未输入密码不可见任何数据。
- 默认落地为服务器概览；侧边栏服务器条目与服务列表的选中态清晰。
- 服务器概览覆盖「目标」中列出的哪吒探针对齐指标（当前值）。
- 概览页趋势图随时间持续更新；探针重启后趋势从空重新累积。
- 服务详情页五块（合成状态 / live 或无法探测 / 版本历史 / 事件 /
  外部链接）齐全，空态有处理。
- 全部样式走 `design/` 语义令牌，组件层无硬编码颜色。
- `npm run build` 通过。

## 已解决的产品决策

- 部署形态：跑在用户服务器上的轻量探针，非托管服务（2026-08-27）。
- 信任边界：仅 localhost + 密码认证（2026-08-27）。
- 指标范围：对齐哪吒探针采集面（2026-08-27）。
- 信息架构：侧边栏（服务器状态 + 服务列表）+ 主内容区详情，服务器与
  服务平级，默认服务器概览（2026-08-27）。
- 视觉：复用 storefront 的 Cursor 暖灰焦橙体系，token 共享自
  `design/`（2026-08-27；2026-08-28 改为相对路径引用，不再是 npm 包）。
- 服务详情五块内容：合成状态 / live 或无法探测 / 版本历史 / 事件 /
  外部链接（`links` frontmatter）。配置在 frontmatter，无 `## Spec`
  （2026-08-27，见 service-runtime-live）。
