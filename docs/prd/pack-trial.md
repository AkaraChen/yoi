# PRD: Pack 沙箱试验（pack-trial）

## 问题与背景

yoi 的核心留存假设（gist 🧪 未验证项）：人 opt-in 装了 yoi skill 之后，对 agent 说一句
「用 yoi 安装 NAME」就能走完部署。这个假设目前没有任何行为证据。在找真人（蝙蝠/拉面）
冒烟之前，先用真实 agent 在隔离环境里把这条路跑几遍，拿到最低成本的行为数据。

## 目标用户

- 作者本人（产品验证）。试验产物是行为记录与体验报告，不是对外内容。

## 用户故事

- 作为作者，我一条命令对某个 pack 发起试验：隔离 Linux 沙箱里的 codex 先装 yoi
  skill，再收到「用 yoi 安装 NAME」，全程自主行动。
- 作为作者，我拿到一份逐轮 transcript 和一份体验报告，回答三个问题：
  流程是否顺畅、询问是否过于繁多、是否有让人不适的环节。
- 作为作者，我能看出流程停在哪一步、为什么（缺密钥、缺依赖、嵌套 docker 等）。

## 目标

- 试验走**完整通路**：装 yoi skill →「用 yoi 安装 NAME」→ skill 选路 → `yoi get` →
  参考安装脚本 → 可用标准。不跳过 skill 层直接喂 pack。
- agent 在隔离环境里跑（沙箱），不直接接触本机文件系统与凭据。
- 每个 pack 产出：逐轮事件记录（transcript）+ 体验报告（顺畅度 / 问题负担 / 不适感 /
  停止点）。
- 三个现有 pack（hermes、openclaw、lobehub）各跑一次。

## 非目标

- 不替代真人验证（gist 的蝙蝠/拉面 assignment 仍然成立）。
- 不要求每个产品都跑到「绿」：缺模型密钥、需要 OAuth、需要嵌套 docker 等都是合法的
  停止点，记录即可。
- 不做 CI 集成、不做评分自动化；报告由人读。
- 沙箱内产出不回流到 pack 内容；试验只观察，不修改产品。

## 流程

1. 构建/启动沙箱：Linux 容器跑 sandbox-agent server，预装 codex。
2. 注入 codex 凭据（从本机 codex 配置提取，或挂载 auth）。
3. 创建 codex 会话（full-access 模式，即 --yolo 等价物）。
4. 第一轮消息：安装 yoi skill（`npx skills add AkaraChen/yoi --skill yoi -g`）。
5. 第二轮消息：「用 yoi 安装 NAME」。
6. 驱动脚本扮演人：agent 每轮停下提问时，按固定策略回答（一律「是，继续」），
   并记录每一次提问。
7. 达到可用标准、撞上不可逾越的墙、或超出轮次上限 → 结束，导出 transcript，
   写体验报告。

## 用户可见状态与失败行为

- 沙箱起不来（docker 不可用、镜像拉取失败）→ 报错并停止，不半成品运行。
- codex 凭据缺失 → 报错并停止，提示怎么补。
- agent 进入死循环（同一问题重复问）→ 轮次上限兜底，报告标记。
- 单 pack 试验失败不影响其他 pack 的试验。

## 验收标准

- 一条命令能对指定 pack 发起试验，不需要手工干预容器。
- transcript 完整记录 agent 的每一轮动作与提问。
- 体验报告显式回答三个问题：流程是否顺畅、问了几次/是否过多、有无不适环节。
- 三个 pack 各有一份报告，停止点与原因明确。
