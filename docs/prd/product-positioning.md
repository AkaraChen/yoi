# PRD: 产品定位（个人部署栈的自托管 OS）

## 问题与背景

人要在自己的 Linux 上跑一套完整部署栈：装软件、记得装过什么、看见现在怎样、
以后还要改和管。宝塔这类面板的答案是把操作简化给人类——菜单、一键安装、
按钮启停。

Agent 时代那层简化没有必要。人不会去点「创建网站」「重启服务」，人会对
自己的编码 Agent 说话。yoi 不把 Linux 收成给人点的面板，而是把机器状态
收成 Agent 可解析的上下文，由 Agent 代管。

商店、Pack、「三分钟跑起来」是这个操作系统的软件源和第一条命令，不是
产品本身。货架上目前多为自托管 Agent，是先选了这些，不构成品类承诺。

## 目标用户

- **服务器拥有者**：单用户，自己的 Linux（一台或多台）。通过自己的编码
  Agent 说话；偶尔打开本机 Dashboard 看一眼。
- **编码 Agent**（Claude Code、Codex 等）：实际操作者。读 yoi 的上下文、
  执行安装与变更、把事实写回 `~/.yoi/`。

## 用户故事

- 作为服务器拥有者，我把 yoi skill 装进 Agent，之后用一句话说出要装或
  要管的东西，而不是去学另一套面板。
- 作为服务器拥有者，我打开商店是为了发现能装什么，不是因为商店就是
  yoi。
- 作为服务器拥有者，我打开 Dashboard 是为了确认机器和服务的现场，不是
  为了点按钮操作。
- 作为 Agent，我能读到服务身份、部署意图、事件账本和（有 `runtime` 时的）
  现场占用，据此决定下一步，并把结果写回。

## 目标

- 产品身份是**个人完整部署栈的自托管操作系统**：统一身份、统一账本、
  统一观察面，跑在用户自己的机器上。
- 操作面是用户已有的编码 Agent（聊天框）。yoi 不另做聊天产品。
- 商店是软件源与获客面。Pack 品类开放，不限定为 Agent 产品。
- Dashboard 是人的只读探针 / 审计面，不是控制面。
- 上下文层记录事实，不编排、不启停、不拦危险操作。危险操作靠人在环
  （cmdspec 打 yes），策略在 Agent。

## 非目标

- **给人用的简化控制面板**：不把启停、建站、改配置做成按钮产品。
- **yoi 自有聊天 UI**：聊天框属于用户的 Agent，不属于 yoi。
- **品类锁定**：不把商店做成「Agent 产品店」；现有货架不代表后续目录。
- **部署引擎**：不校验 Plan、不自动回滚、不阻止危险操作。
- **登记手续的细节**不在本 PRD：见 `docs/prd/os-registration.md`。
  手续文本在 `skills/yoi/references/landing.md`。

## 范围与用户流

主路径（人 → Agent → 机器）：

1. 人在商店或口头指定一个 Pack（或任意要部署的软件）。
2. 人对自己的 Agent 说话（例如「用 yoi 安装 NAME」）。
3. Agent 按 yoi skill 拉取知识、等人确认、在目标 Linux 上执行。
4. Agent 自认结束后用 `yoi-server` 把 Service / Release / Event 写入
   该机 `~/.yoi/`（契约见 `docs/prd/os-registration.md`）。
5. 人若要看现场，经 SSH 隧道打开该机 Dashboard。
6. 之后的升级、排查、多机分辨，仍由人对 Agent 说，Agent 读上下文再做。

商店（`web/`）只承担发现与 skill 入口。CLI 是 Agent 的系统调用，不是
给人日常敲的主界面。

## 用户可见状态与失败行为

- 对外叙事必须把 yoi 说成部署栈 OS，把商店说成软件源。不得再把「部署
  技能商店」写成产品定义。
- 人未确认时，Agent 不得安装 Pack、CLI 或探针。
- Dashboard 无控制按钮；缺 `runtime` 时服务为「无法探测」，探针不扫整机。
- 商店无某品类时不解释为战略收缩；空货架或偏科货架都不是定位失败。

## 验收标准

- `docs/spec.md` 的产品身份是个人部署栈的自托管 OS；商店是软件源。
- README 与 `AGENTS.md` 与上述身份一致；不把货架品类写成产品边界。
- 操作者被写成用户的编码 Agent；Dashboard 被写成只读观察 / 审计。
- 红线不变：opt-in、人在环、诚实卸载、无 2code 捆绑、AFF 限制见 spec。
- 不出现「yoi 提供聊天界面」或「yoi 是 Agent 产品商店」的产品承诺。

## 排除项与已解决的产品决策

- 产品 = 个人完整部署栈的自托管 OS（2026-09-01）。
- 商店 = 软件源与获客，不是产品本身（2026-09-01）。
- 货架现有 Agent 产品是选取结果，不是品类承诺（2026-09-01）。
- 操作者 = 用户的编码 Agent；人的最终界面是对该 Agent 的聊天框
  （2026-09-01）。
- 对标宝塔的问题空间，答案相反：展开上下文给 Agent，而不是把操作收进
  GUI（2026-09-01；技术约束见 `docs/adr/agent-as-operator.md`）。
- 「三分钟跑起来」可以继续当第一条命令的获客话术，不能当产品定义
  （2026-09-01）。
- 2026-08-13 的双面结构（初级部署 / 高级清场）仍未选型，不在本定位里
  恢复为承诺。
