# PRD: /shop 货架过滤

## 问题与背景

`/shop` 是全量 Pack 货架。访客若已有关键词（slug 或简介里的词），只能靠扫网格。
agent 侧已有 pack 搜索（yoi skill 的 HTTP 配方：slug / excerpt，大小写不敏感
包含），网页没有对等入口。
本功能撤回 `docs/prd/web-storefront.md` 初版「不做站内搜索/筛选」中针对
`/shop` 货架的那一部分；不做全站搜索，也不做独立搜索页。

## 目标用户

- 打开 `/shop`、已经知道大概名字或关键词的访客。
- 拿到 `/shop?q=…` 链接的访客。

## 用户故事

- 作为访客，我在 `/shop` 输入关键词，网格立刻只留下匹配的 Pack。
- 作为访客，我打开带 `q` 的 `/shop` 链接，看到的就是过滤后的货架。
- 作为访客，没有匹配时页面直说没有，而不是一片空白网格。

## 目标

- `/shop` 就地缩小货架，不离开当前页。
- 当前查询可寻址：`/shop?q=…`；清空后回到干净的 `/shop`。
- 匹配字段与 yoi skill 的 pack 搜索配方一致：slug、excerpt。

## 非目标

- 不新增搜索页、搜索 API、或 `/packs.json?q=`。
- 不搜 `page.mdx` 正文，不做分类/标签筛选，不做「你是不是想找」。
- 不改首页预览、详情页、吸顶导航；过滤控件只出现在 `/shop`。
- 不改 yoi skill 搜索配方（`skills/yoi/references/packs.md`）的契约。

## 范围与用户流

1. `/shop` 页头附近有常驻查询输入（搜索按钮若存在，只是附属，不是主表面）。
2. 输入后网格立刻按查询过滤；`?q=` 用 history replace 同步（不堆历史记录）。
3. 无查询或 `q` 为空：全量货架，计数仍为「共 N 个 Pack」。
4. 有查询：网格只含匹配卡，计数反映当前匹配数。
5. 零匹配：直说「没有匹配的 Pack」；查询留在输入框和 URL。清空输入即回到全量。

## 用户可见状态与失败行为

- 默认 / 空 `q`：与现网相同的全量网格。
- 有匹配：只渲染命中的 `ProductCard`。
- 零匹配：不渲染空网格，文案为「没有匹配的 Pack」。
- 查询只匹配 slug 与 excerpt 的子串（大小写不敏感）；空白查询视为无查询。

## 验收标准

- `/shop` 有常驻查询输入；输入即时过滤网格。
- 打开 `/shop?q=hermes` 只看到 slug 或 excerpt 包含 `hermes` 的卡（大小写不敏感）。
- 打开 `/shop?q=` 或 `/shop` 看到全量货架与「共 N 个 Pack」。
- 打开必不命中的 `q` 时，页面出现「没有匹配的 Pack」，输入框仍保有该查询。
- 清空输入后 URL 回到 `/shop`，网格恢复全量。
- 首页、详情页、站点头不出现搜索控件；`/packs.json` 仍是无查询参数的全量索引。

## 已解决的产品决策

- 这是 **shop filter**（货架就地过滤），不是站点搜索，也不是 agent 侧的 pack 搜索。
- 查询进 URL（`q`）；空查询不保留无意义的 `?q=`。
- 空结果老实说明没有匹配，不提供猜词或推荐。
